# Reviewed report-fact Q&A — first backend slice

This is a separate, reviewer-curated index for facts that are not drilling events. It is deliberately **not** generative question answering. A reviewer records a stable `fact_key`, a concise answer, and an exact supporting quote on one extracted passage. The API checks that the quote occurs in that passage and the dataset passes the existing provenance/qualification gate, then records an append-only decision-ledger entry. OCR text is not promoted by extraction alone.

`POST /api/v1/report-facts` requires a reviewer token and `dataset_id`, `passage_id`, `fact_key`, `answer`, `quote`, and review rationale. OCR-derived facts additionally require explicit confirmation that the page image was checked. `POST /api/v1/report-facts/ask` accepts `dataset_id` and `fact_key`, returning `answered` with document/page/text-version citations, `no_answer`, or `conflict` when reviewed answers disagree. A reviewer can withdraw an incorrect fact through `POST /api/v1/report-facts/{id}/withdraw`; the earlier decision remains in the ledger. It does not expose whole OCR pages to viewers.

The reviewer UI in the evidence room displays the selected source page, records a cited fact, and creates a curated reader question. `POST /api/v1/report-facts/questions` maps exact wording to a stable fact key only after a fact is approved, or records a `conflict_blocked` question with a reason. The Report questions tab uses `POST /api/v1/report-facts/ask-question` to show the reviewed answer and citations, no-answer, or conflict. The UI was rehearsed on an isolated synthetic test database at desktop and mobile widths.

This does **not** accept arbitrary natural-language questions, rank passages, synthesize multi-hop answers, adjudicate semantic equivalence, or assert the public benchmark's 10 report-fact questions have been answered. Fact keys must include enough scope (for example well/report and subject) to avoid mixing wells. The NOD-511 depth discrepancy remains blocked; no public staged draft was approved or copied into this table. Next steps are citation audit on newly reviewed passages, lexical/semantic/hybrid retrieval, and an untouched held-out evaluation. The public preview database is not migrated by this branch.
