# Reviewed report-fact Q&A — first backend slice

This is a separate, reviewer-curated index for facts that are not drilling events. It is deliberately **not** generative question answering. A reviewer records a stable `fact_key`, a concise answer, and an exact supporting quote on one extracted passage. The API checks that the quote occurs in that passage and the dataset passes the existing provenance/qualification gate, then records an append-only decision-ledger entry. OCR text is not promoted by extraction alone.

`POST /api/v1/report-facts` requires a reviewer token and `dataset_id`, `passage_id`, `fact_key`, `answer`, `quote`. `POST /api/v1/report-facts/ask` accepts `dataset_id` and `fact_key`, returning `answered` with document/page/text-version citations, `no_answer`, or `conflict` when reviewed answers disagree. A reviewer can withdraw an incorrect fact through `POST /api/v1/report-facts/{id}/withdraw`; the earlier decision remains in the ledger. It does not expose whole OCR pages to viewers.

This first slice does **not** accept arbitrary natural-language questions, rank passages, synthesize multi-hop answers, adjudicate semantic equivalence, or assert the public benchmark's 10 report-fact questions have been answered. Fact keys must include enough scope (for example well/report and subject) to avoid mixing wells. The NOD-511 depth discrepancy remains blocked; no public staged draft was approved or copied into this table. Next steps are a reviewer UI, question-to-fact mapping and citation audit on newly reviewed passages, then lexical/semantic/hybrid retrieval and an untouched held-out evaluation. The public preview database is not migrated by this branch.
